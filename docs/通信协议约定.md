# 通信协议约定

> 版本 v0.1.0
> 范围：上位机（Rust，`hmi/`）↔ 编程器固件（STM32F103，`firmware/`）之间的**协议依据**。
> 两侧实现如有冲突，以本文为准；修改本文需同步两侧。当前协议仅覆盖烧录功能；仿真/调试协议后续另立文档。
> 使用说明：`docs/固件使用说明.md` / `docs/上位机使用说明.md`
>
> 协议栈分两层：
> - **L1：上位机 ↔ 编程器**（CMSIS-DAP 厂商命令，本文 §1~§3）
> - **L2：编程器 ↔ 目标 MCU**（DBG 单线 UART，New8FX 串行编程协议，本文 §4~§7，由编程器固件本地执行，上位机不直接感知字节级细节）

---

## §1 L1 传输层（CMSIS-DAP v1/v2 自适应）

- 编程器在**同一 USB 配置**中提供两个 DAP 接口（非复合 Hub）：
  - Interface 0 = **CMSIS-DAP v1**（HID 类）——Win7 产线保底，全平台免驱；
  - Interface 1 = **CMSIS-DAP v2**（Bulk，WinUSB）——Win8.1+/Linux/macOS 优先。
- 上位机策略：**枚举优先 v2，失败/不存在回退 v1**；OS 版本判定仅用于 UI 提示。
- DAP 通信模型：严格**请求-响应**，一包完成；请求与响应首字节均为命令 ID。
- F2MC 全部操作走厂商命令 **`ID_DAP_Vendor0` = `0x80`**（ARM 官方预留 0x80~0x9F）；标准 DAP 命令（0x00~0x7F）服务 STM32 路径，由 probe-rs/OpenOCD 发出，与本文无关。
- 包长：v1 = HID 报告 64 B（首字节为命令 ID；主机侧另有 1 B ReportID=0x00 前缀，共 65 B）；v2 = Bulk 包 ≤64 B（FS）。**应用层统一按单包载荷 ≤ 56 B 设计**（两通道取最小余量）。
- 编程器执行单条命令期间**不响应新命令**（上位机串行发命令）。

## §2 L1 应用帧（vendor 命令封装）

```
请求:  [0x80] [CMD] [LEN_L] [LEN_H] [PAYLOAD(LEN ≤ 56 B)]
响应:  [0x80] [STATUS(见 §3.3)] [DATA...]
```

- 多字节整数一律**小端（LE）**。
- DAP 为同步请求-响应 + USB 可靠传输，故**不再需要** SOF/SEQ/CRC16；单包 56 B 上限使大块读写走 BEGIN/DATA/COMMIT 三段（§3.1）。
- 响应首字节 ≠ 0x80、缺 STATUS 字节或长度与命令语义不符 → 传输错误，重试一次，仍失败上报。
- ⚠ 上位机收到状态码 ≠ 0x00 时，不得继续后续流程步骤（除明确标注可重试的场景）。
- ⚠ **响应迟到处理**：上位机命令超时后**不得立即发新命令**——固件可能仍在执行（如 ENTER_PGM 失败路径最长 ~7 s），迟到的响应会错位成下一命令的响应。应先持续读直到迟到响应到达（或 GET_STATE 轮询确认固件空闲）后再继续。

## §3 L1 命令集

### 3.1 命令表

| CMD | 名称 | 请求 PAYLOAD | 响应 DATA（STATUS 之后） | 上位机超时 | 说明 |
|---|---|---|---|---|---|
| 0x01 | PING | 空 | `"F2MC-LINK"` + FW版本(3B) | 1 s | 连通性与固件版本 |
| 0x02 | SET_POWER | [on:1B] | — | 5 s | 目标 VCC 开关（F2MC-LINK v1.1：PA8 → EL817+SS8050 光电管开关，通流 ≤50mA 仅裸片烧录）。on=1 上电并做 3 s 上升确认，过载/短路/未接目标自动关断并回 `PWR_FAULT(0x0C)`；on=0 断电且状态机复位 IDLE（§3.2）。ENTER_PGM 内部已含自动断电→上电，上位机一般无需显式调用 |
| 0x03 | ENTER_PGM | 空 | — | **10 s** | 完整进模式序列：VCC 上电(或检测)→DBG 拉低 1.2 s→释放→握手→时钟修改（§5.1~5.3）。⚠ F2MC-LINK v1.1 起内部含自动断电→上电，典型 ~3-4 s（手动上电时 ~1.6 s）；**目标无响应的失败路径固件最长 ~7 s**（握手 200 次重试）才回 TIMEOUT——上位机超时后必须先 GET_STATE 等固件返回再发新命令（防响应迟到错位，见 §2）；固件进入本命令时自动把 DBG 波特率归位 62500（QUIT 后可直接重进） |
| 0x04 | ERASE | [AddrH, AddrL] | — | **90 s** | 整片擦除 Addr=0x0000；扇区擦除 Addr=扇区内地址。**SYNCED 态=§5.4 pre-init 形式（62500）；RW_MODE 态=§5.6 读写模式内擦除（500K），状态保持 RW_MODE**（烧录完成后可直接再擦）。固件侧单发不重试、等待上限 60 s（实测整片擦除 ~1.3 s；超时≠失败，应由上位机决定是否重发） |
| 0x05 | FLASH_INIT | [XX, YY] | — | 5 s | 下载 INIT DA.BIN（§6）并切换波特率。MB95630H: `XX=0x02, YY=0x7C` |
| 0x06 | WRITE_BEGIN | [AddrH, AddrL, LenH, LenL] | — | 1 s | Len ≤ 512 B；固件分配缓冲、清零偏移 |
| 0x07 | WRITE_DATA | [Data ≤ 56 B] × ⌈Len/56⌉ | — | 1 s/包 | 顺序追加到缓冲；最后一包可短 |
| 0x08 | WRITE_COMMIT | 空 | — | 5 s | 固件将缓冲数据一次性执行 L2 写（§5.7） |
| 0x09 | READ_BEGIN | [AddrH, AddrL, LenH, LenL] | — | 2 s | Len ≤ 1024 B；固件立即执行 L2 读（§5.8）入缓冲 |
| 0x0A | READ_DATA | 空 | Data ≤ 56 B | 1 s/包 | 顺序取回，取满 Len 为止；小数据（如 NVR 3 字节）一次取完 |
| 0x0B | CR_TRIM_WRITE | [AddrH, AddrL, Data] | — | 2 s | NVR 校准值回写（§5.9）。⚠ **真机 DA 不实现 Spec 7.9 的 0x55 命令（回 0xFF）**，上位机请改用普通写路径（WRITE_BEGIN/WRITE_DATA/WRITE_COMMIT）写 0xFFBB；本命令保留但会返回 ACK_ERROR |
| 0x0C | QUIT | 空 | — | 2 s | 退出读写模式（§5.10）。⚠ 退出后固件把 DBG 波特率**归位 62500**（目标退回 bootloader 世界），可直接重新 ENTER_PGM，无需重启编程器 |
| 0x0D | RESET_RUN | 空 | — | 2 s | 无 RST 硬件，固件恒回 `UNSUPPORTED` 并把状态机复位到 IDLE；上位机应提示用户**人工断电重启**运行用户程序 |
| 0x0E | GET_STATE | 空 | [state:1B, last_error:1B] | 1 s | 排障用 |
| 0x0F | WRITE_SECURE | 空 | — | 2 s | 向 0xFFFC 写 0x01（安全锁，§7） |
| 0x10 | SEND_BREAK | 空 | — | 1 s | 向 DBG 发 UART Break（通信恢复手段） |
| 0x11 | DISCONNECT | 空 | — | 1 s | **上位机断开通知**：LED 熄灭 + 状态机复位 IDLE。目标侧状态不变；重连后从 ENTER_PGM 重新开始。GUI/CLI 关闭设备前应发送 |
| 0x12 | ABORT | 空 | — | 1 s | **强制中止当前长操作**（ENTER_PGM 等待上电/握手、ERASE 60 s 等待、读等待）。带外生效：固件 USB ISR 收到本命令立即置中止标志，长操作轮询退出并以 `ABORTED(0x0B)` 应答原命令；ABORT 本身排队后回 OK。无操作在执行时发送无害（幂等）。⚠ 中止 ENTER_PGM 后目标可能处于半初始化态，重试前建议断电重启目标 |

### 3.2 状态机约束（编程器固件维护）

```
IDLE →(ENTER_PGM)→ SYNCED →(ERASE)→ ERASED →(FLASH_INIT)→ RW_MODE
                  SYNCED →(FLASH_INIT)→ RW_MODE（仅校验/读取路径，不擦除）
RW_MODE →(WRITE_*/READ_*/CR_TRIM_WRITE/ERASE)→ RW_MODE
RW_MODE →(QUIT)→ SYNCED；任何状态 →(RESET_RUN/SET_POWER off)→ IDLE
```

- ERASE(0x04) 在 SYNCED（pre-init 形式）与 RW_MODE（读写模式内擦除，状态保持）均可用；WRITE_*/READ_* 仅在 RW_MODE 可用；状态错误返回 `STATE_ERROR`。
- FLASH_INIT(0x05) 在 SYNCED 与 ERASED 均可用——**仅校验/读取流程**（不能擦除毁数据）：`ENTER_PGM → FLASH_INIT → READ_*`；L2 上 DA 加载不依赖先擦除（Spec 7.5 无此前提）。
- WRITE_DATA 必须紧跟 WRITE_BEGIN（未达 Len 前），READ_DATA 必须紧跟 READ_BEGIN（未取满前）；顺序错乱返回 `STATE_ERROR`。
- ⚠ FLASH_INIT 后目标波特率切到 500 Kbps（XX=0x02），固件必须同步切换自身 UART 波特率，否则后续全部失败。

### 3.3 状态码

| 码 | 名称 | 含义 |
|---|---|---|
| 0x00 | OK | 成功 |
| 0x01 | TIMEOUT | 目标应答超时（含擦除 60 s 等待） |
| 0x02 | SECURITY_LOCKED | 收到 0xFD——目标已加安全锁（§7） |
| 0x03 | ACK_ERROR | 收到非预期 ACK 值 |
| 0x04 | TARGET_CHK_ERROR | 目标侧校验和错误（无响应或乱码） |
| 0x05 | BAD_PARAM | 请求参数非法（长度/地址/状态） |
| 0x06 | UART_ERROR | 帧错误/溢出等底层错误 |
| 0x07 | STATE_ERROR | 当前状态不允许该命令 |
| 0x08 | FRAME_CRC_ERROR | L1 帧 CRC 错误（保留，当前固件未用） |
| 0x09 | BUSY | 上一条命令未执行完 |
| 0x0A | UNSUPPORTED | 硬件/固件不支持（如无 RST 引脚的 RESET_RUN） |
| 0x0B | ABORTED | 操作被 ABORT(0x12) 中止 |
| 0x0C | PWR_FAULT | 目标电源异常（过载/短路/未接），已自动关断 |

## §4 L2：New8FX 串行编程协议（编程器 ↔ 目标 MCU）

> 依据：富士通《New8FX Serial PGM》规范 V1.3.0（下称 Spec，§5/§6/§7）。
> ⚠ L2 全部由**编程器固件本地执行**（字节间隔、波特率切换、擦除长等待（固件 60 s）都是时序关键，禁止由上位机逐字节遥控）。

**链路参数**：单线半双工 UART（DBG 引脚），初始 **62500 bps**（8N1，LSB first，空闲高），编程器为主机。FLASH_INIT 后按 BIN 参数切 **500000 bps**。

**通用帧约定**：5 字节命令帧 = `功能码/AddrH | Data/AddrL | 参数 | Checksum | ACK`；Checksum = 前 3 字节之和（仅低 8 位）；正常 ACK = 0x00；**0xFD = 安全锁**。

---

## §5 L2 命令序列（MB95630H 参数）

### 5.1 进 PGM 模式（Spec 5.2）
VCC 上电（L→H）时 DBG 保持低；≥1 s 后 DBG 拉高 → 进 PGM 模式。固件实现：DBG **推挽拉低**（目标无电，无倒灌路径）→ 等待 VCC 上升 >2.5 V（10 s 超时）→ **等 VCC 稳定**（每 50 ms 采样，连续 3 次相差 <100 mV，10 s 超时）→ **定时 1.2 s** → 释放 DBG（上拉电阻拉高）。
⚠ 必须有 VCC 上升沿；RST 不参与模式进入。

### 5.2 握手（Spec 7.1）
`0x55` →(间隔 ≥3 ms)→ `0xAA` →(等 ≥6.6 ms)→ 读 ACK；ACK=`0x51` 成功。
重试 ≤200 次（Spec 给 5000 次，实测典型 2 次成功，200 次≈5 s 足够且让失败路径落在 10 s 上位机超时内）；200 次失败 → 重新上电重来。成功后**等 1 ms**再发后续命令。

### 5.3 时钟修改（Spec 7.3，握手后 1 ms 发）
字节间隔 **<250 µs**：
- 帧1：`00 00 07 07` → ACK 0x00
- 帧2：`03 00 D8 DB` → ACK 0x00（**0xFD → 安全锁，须先整片擦除**）

### 5.4 擦除（Spec 7.4，FLASH_INIT 之前）
字节间隔 **≥1 ms**：
- 帧1：`00 00 0C 0C` → ACK
- 帧2：`05 00 60 65` → ACK
- 帧3：`06 AddrH AddrL Sum` → ACK（**整片擦除 Addr=0x0000**；扇区擦除 Addr=扇区内任意地址）
- ⚠ 末帧 ACK 等待超时 **>35 s**（Spec 要求；固件实现为单发等 60 s——实测整片擦除 ACK ~1.3 s 即返回，超时≠失败）；末帧（f3）**不可重发**（会撞忙中的目标），f1/f2 头帧才可重试。

### 5.5 FLASH_INIT（Spec 7.5）
- 头：`00 00 0C 0C`→ACK；`05 00 60 65`→ACK；`00 00 90 90`→ACK
- 体：INIT DA.BIN（§6，**真机用 YM02 版本共 141 字节**），逐字节发：`03 00 <data> <sum(03+00+data)>` → ACK，重复至发完
- 尾：`0A 00 00 0A` → ACK
- 完成后目标进入读写模式，**固件切 UART 到 500000 bps 并等 10 ms**（让目标完成自身 UART 重配）

### 5.6 擦除（Spec 7.6，读写模式内）
`AddrH AddrL 00 00 AA` → ACK（整片擦除 Addr=0x0000）。用于 CR Trimming 修复等场景。

### 5.7 写（Spec 7.8）
`AddrH AddrL LenH LenL 0xFF` + Len 字节数据（连续发）；总字节数 = Len+5。完成后**固件等 10 ms**（Spec 说 ~1 ms，真机充电泵忙远超）。
⚠ **实测：RW 期写数据必须 150 µs/字节节拍**（固件 `GAP_RW_US`）——DA 每字节处理 ~50-66 µs（Spec 7.14），背靠背零间隔会丢字节；DA 字节计数失配后会把后续命令帧吃成写数据，链路永久错位。
⚠ 单次 Len 由固件按 L1 WRITE 分块（≤512 B）决定。

### 5.8 读（Spec 7.7）
`AddrH AddrL LenH LenL 0x00` → 目标连续回 Len 字节（字节节拍 ~66 µs）。总字节数 = Len+5。
可读全 64 KB 地址空间（含 IO 区 0x0FE4 等）。
⚠ **写后立即读时首字节响应可能延迟 200 ms+**（DA 忙于编程）；固件首字节窗口 100 ms，超时 break 重试 ×2。

### 5.9 写 CR 校准（Spec 7.9）
`AddrH AddrL 00 Data 55`（单字节写，用于 NVR 回写）。
⚠ **真机 DA 不实现本命令**（实测回 0xFF；YM02 嗅探全程未见 0x55 命令）——CR 恢复改用 §5.7 普通写路径写 0xFFBB 起 3 字节。

### 5.10 退出（Spec 7.10）
`xx xx xx xx 88`（前 4 字节任意保留值，建议 0x00）。仅读写模式内有效。

### 5.11 通信恢复
命令失败重试前先 `SEND_BREAK`（UART Break，约 1~2 帧时长）复位目标通信状态。任何无法恢复的失败 → 重新走完整上电流程（Spec：*encountered any failure → power on again*）。

## §6 INIT DA.BIN

FLASH_INIT 需向目标上传一段 Download Agent（DA）代码，使目标进入读写模式。

⚠ **真机勘误**：Spec Table 7-1 给出的 **198 字节版本在真 MB95630H 上不可用**（上传后 DA 对一切读命令无响应）。本固件内嵌的是**从 YM02 编程器嗅探提取的 141 字节版本**（参数 0x1D/0x1F 及中间代码段均有差异），见 `firmware/App/new8fx.c` 的 `INIT_DA_BIN`；RW 期波特率 500K 由 BIN 内 `85 26 02` 参数决定（对应 FLASH_INIT 参数 `XX=0x02, YY=0x7C`）。上位机不需要 DA.BIN 内容。

## §7 安全锁与 NVR 规则（两侧都必须遵守）

- **安全锁**：`0xFFFC = 0x01` 写入后不立即生效，断电复位或 QUIT 后生效。生效后仅握手 + 整片擦除可用，其余命令回 `0xFD` → L1 状态码 `SECURITY_LOCKED`。
  - 上位机流程：**只在用户显式加 `--secure` 时**最后写 0xFFFC；收到 SECURITY_LOCKED 时提示并自动执行整片擦除解锁后重试一次。
- **NVR 区（0xFFBB~0xFFBF）**：存 CR 时钟校准/看门狗 ID。
  - ⚠ **Blank Check 与 Verify 跳过 0xFFBB、0xFFBC、0xFFBD 三个地址**（Spec 7.12/7.13）。
  - ⚠ 上位机解析 hex 时若发现数据落在 0xFFBB~0xFFBF，默认剔除并告警（防止覆盖校准值）。
  - **CR Trimming 检查**（Spec 7.11，0.18µm 产品含 MB95630H）：擦除成功后读 `0xFFBB/0xFFBC/0xFFBD` 与 `0x0FE7/0x0FE4/0x0FE5`（RAM 镜像）比较，不一致则**用普通写命令把 RAM 镜像值写回 0xFFBB**（Spec 7.9 的 CR_TRIM_WRITE 0x55 命令真机 DA 不实现，实测回 0xFF；擦除后 MCU 通常已自动回写 NVR，检查多为确认）；编程结束后再查一次。

## §8 性能与时间预算（验收参考）

| 阶段 | 典型耗时 |
|---|---|
| 进模式（含 1.2 s 等待） | ~1.3 s |
| 握手 | 11~202 ms |
| 时钟修改 | ~10.6 ms |
| FLASH_INIT（141 B） | ~80 ms |
| 整片擦除 | 实测 ~1.3 s（固件等待上限 60 s） |
| 读 @500K | ~66 µs/B（DA 字节节拍），36 KB ≈ 2.5 s |
| 写 @500K | ~170 µs/B（含 150 µs 间隔+DA 编程），36 KB ≈ 6.5 s |
| 整片烧录+校验（35 KB，全量实测） | ≈ 25~40 s（含 USB 分块开销） |
